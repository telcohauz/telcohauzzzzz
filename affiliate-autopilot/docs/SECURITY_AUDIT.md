# Security audit — 2026-11-17

Scope: added affiliate-autopilot module only. Existing Telcohauz applications were neither modified nor certified. This is a development security assessment, not a production penetration test or a guarantee.

## Executed checks

- Bandit 1.8.6: final scan **0 unsuppressed findings**, JSON in `evidence/bandit.json`. Initial dynamic SQL flags were eliminated with fixed statements. Two narrow subprocess rules are documented/suppressed: importing subprocess and invoking a bounded, shell-free local FFmpeg command with generated paths. FFmpeg uses absolute `/usr/bin/ffmpeg`, 120-second timeout and one thread. Suppression does not establish host binary security.
- pip-audit 2.9.0: pinned optional Pillow 13.0.0, **0 known vulnerabilities returned by the feed**, JSON in `evidence/pip-audit.json`. Initial installed Pillow 12.3.0 had 42 reported advisories and was replaced in the pinned requirements. Final real render tests used isolated Pillow 13.0.0. Vulnerability feeds change.
- Local static policy check: no eval/exec or shell=True. Python compilation and JavaScript syntax checks passed.
- Auth/permission tests: unauthorized API requests denied; no token in URLs or logs; eligible account required for publication/financial import; illegal queue transitions blocked; 32-character minimum owner token; only local CLI can activate an account.
- Input checks: parameterized SQL, positive bounded monetary integers, permitted enum states, HTTPS provenance, source timestamps, 256 KiB HTTP body limit, 1000 financial/metric records per batch.
- Recovery/resource tests: transactional concurrent claim, retry exhaustion, lease recovery, monthly job and rendering caps, failed financial batch rollback.
- Browser check: actual Chromium owner login and pause/resume, honest empty metrics, mobile overflow check, no browser JavaScript errors. CSP forbids inline scripts; UI uses textContent for imported values.

## Protections implemented

Default global pause, disabled platforms, no external API keys, separate environment secrets, SQLite 0600 permissions, no raw identity/payment credentials, generic error codes instead of raw exceptions, hardcoded query identifiers, foreign keys and unique constraints, audit actions and notifications, no CORS permission, cross-site POST rejection, no-store and anti-framing headers, in-memory dashboard token only, bounded subprocess and job execution. Workflow token has read-only contents permission; checkout does not persist credentials. CI/maintenance remain manual pending verified free capacity.

## Remaining release blockers and limitations

- Python standard-library HTTP server is a private control plane, not a hardened internet-facing server. TLS proxy, host-level rate/concurrency limits, dedicated OS user, firewall, private access and persistence need deployment verification.
- Single shared owner credential; no per-user roles, MFA, session expiry, secret-manager integration or immediate individual session revocation. Owner token rotation needs service restart. No automated expiry monitor.
- SQLite file access is privileged local access, not tenant RLS. A future Supabase/Postgres implementation must add and test least-privilege roles and policies. No cloud database migration was run.
- Export authenticity and publication URLs are owner attestation; no official API signature/live verification is implemented. HTTPS references can still point at incorrect data. No network fetch is made, preventing source URL SSRF but not false owner input.
- Financial reconciliation, paid/unpaid allocation and overlap detection for metric windows remain incomplete. Imported payouts are labelled unreconciled.
- Media caps are checked before rendering but not transactionally reserved across multiple renderer processes. Run one renderer until a durable quota reservation service is implemented. No cloud disk cap or asset cleanup verified.
- Audit logs can be changed by a local DB administrator; no tamper-evident archive. Backup restore, retention policy, disaster recovery and cloud quota enforcement remain unverified.
- Python/SQLite/FFmpeg/OS binaries, browser tooling, GitHub Action implementation and the original npm application were outside the dependency scan. Optional media requirement is pinned but not hash-locked.
- External notifications, credential rotation automation and policy-change monitoring are not connected. No official current age/API/publishing eligibility claim is made.

No real customer records or affiliate credentials were accessed. No purchases, clicks, engagement, payouts or commercial traffic were generated by the tests.
